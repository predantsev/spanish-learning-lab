# Acceptance and release evidence

These are future executable scenarios, not tests passed by this documentation PR. Use synthetic profiles, injected clock/filesystem/transport faults and immutable fixture revisions. A test passes only when assertions are observed, not because code/schema looks plausible. Record command/version/artifact hash/result and failure trace. Domain, API, actual audio, real device and security checks are separate evidence types.

## Real environment gates

Desktop planning probes confirmed macOS26.6.2 and Node25.2.1/npm11.6.2; Chrome version is unconfirmed after a failed later path probe (RESEARCH.md). These are not application tests. At release record actual OS/Chrome/Node/build/native SQLite versions; rerun core flows under current installed Chrome. Verify normal `.localhost` browser resolution, local package launch/stop/restart, full offline assets, typing/shortcuts/audio/recovery and no unrelated process/config changes.

Real iPhone/iOS/Safari version is **unconfirmed**; record it at test time. Required phone tests: input/accent keyboard, multiline/visible action with software keyboard, focus/reference sheet/back navigation, user-gesture playback/rate/replay, audio error, phrase/material details, viewport/scroll and saved-draft recovery. Desktop Playwright WebKit/mobile emulation does not satisfy actual iPhone gate. For pre-release device QA, use USB Safari inspection or a temporary synthetic-only test listener bound to one explicit private LAN interface, with authentication, firewall status recorded, no UPnP/public tunnel, and only while the tester deliberately starts it. Restore loopback default and stop the exact owned test process afterwards. This is optional test-only configuration requiring explicit execution authorization if firewall/network changes are needed; never expose a real profile. Remote/persistent phone use remains deferred. Lack of actual-device access is reported as a release blocker, not a reason to ask routine product questions during planning.

## Human-only execution actions

No human Spanish teacher is assumed. Owner interaction may still be required for OS trust/credentials, explicitly authorized billing or an actual iPhone session; prepare scripts/instructions and exact scope first. UI confirmation for a real restore is intentional and does not conflict with autonomous planning. Do not silently import real profile backups into a test suite or send personal answers/audio to any reviewer.

## Release report and go/no-go

Record app Git SHA/build hash; package/Node/lockfile/pack/schema hashes; exact OS/browser/device and tool versions; each A-case command/manual procedure/result/evidence path; sources/calibration/model/effort and actual media-file review receipts; complete content coverage; privacy/security/backup restore drill; remaining limitations/known nonblocking issues and rollback instructions. Public reports contain only synthetic data and redacted paths; private evidence stays outside Git.

Required gate failure = no complete-owner handoff. Every89 lesson and14 optional check must be navigable, every required file local and reviewed, and API+skill tested. No waiver by a happy-path test, a model's approval, screenshot, passing schema or partial vertical slice. Known nonblocking cosmetic issues may be listed with reproducible steps and a fix issue. Learning effectiveness/long-term recall remain unverified after release until actual use/evaluation supplies evidence.

Planning-PR checks are narrower: JSON/schema/OpenAPI structural validation, examples, source-ID/cross-reference completeness, decision/gate coverage, independent document review and whitespace/diff checks. They do not execute any A-case above.
