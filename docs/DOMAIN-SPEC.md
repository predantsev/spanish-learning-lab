# Domain, durability and learning evidence

Normative first-release mechanics under C-084; [product authority](COURSE-DESIGN.md) and [handoff](IMPLEMENTATION-PLAN.md) apply. All dates/values below are calibratable product defaults, not scientific retention claims. Examples and fixtures are synthetic.

## Identity, revisions and transactions

One private profile has a UUID and a monotonically changing `profileEpoch`. Stable curriculum IDs retain their existing spelling. New entities use UUIDs; atomic skill IDs use descriptive immutable slugs linked to a broad objective. A target is `(skillId, modality)`; modalities are `written-form`, `context-choice`, `reading-meaning`, `listening-meaning`, `dictation`, `phrase-recall`, `construction-use`. Do not infer one modality's success from another. A task may assess several explicit targets, but each has an independently attributable result. Prerequisite vocabulary/support is not automatically an assessed target.

Content entities have immutable revision IDs, SHA-256 digests, author/reviewer/source provenance and states `draft`, `needs-review`, `ready`, `retired`, `quarantined`. A logical ID points to an active ready revision; editing creates a new revision. An attempt pins task/answer-key/audio/rubric revisions. Collections reference shared phrase IDs; removing a collection does not delete phrases or histories. Removing a phrase archives it and pauses new automatic practice; historical references remain readable. Confirm destructive phrase/draft actions with a recoverable undo; physical profile replacement is separately gated.

Minimum SQLite tables (versioned migrations, FK enforced): profiles; curriculum_nodes; content_revisions; active_content; assets; review_reports; skills; target_states; sessions; contexts; drafts; attempts; target_results; support_events; adjudications; learner_preferences; phrase_records; collections; collection_members; practice_sets; event_log; mutation_receipts; backup_records; import_attestations. No personal field is tracked in the public repository. `event_log` has monotonically increasing `eventSeq`, UTC timestamp, profileEpoch, event kind/entity IDs and schemaVersion. Projection `target_states` is rebuildable, with `projectionVersion` and lastEventSeq. Use unique constraints for operation IDs and foreign keys for all pinned references.

Single service/single writer; `foreign_keys=ON`, `journal_mode=WAL`, `synchronous=FULL`, `busy_timeout=5000`. Use prepared statements and bounded read queries. Each command transaction atomically checks authentication/epoch/receipt/revisions, appends events, updates projections and writes the mutation receipt. No network/async work inside a synchronous SQLite transaction. Return success only after commit. A disk-full/locked/corrupt failure rolls back the entire command; no success toast, grade or due-date mutation. Health reports degraded storage without exposing private text. A failed migration retains the pre-change snapshot and old binary; never keep running a half-migrated profile.

Every write has a UUID `operationId`/`Idempotency-Key` and a canonical-body digest. Scope uniqueness by profile + operationId, not token or browser tab. Authenticate first, then look up an existing receipt **before** checking current revisions. Same operation/kind/body returns its original receipt even after a lost response or token rotation (owner token-creation secret redelivery and post-restore authentication have explicit safe exceptions in API.md); different body/kind returns 409. Store receipt IDs/hash/result references permanently in the profile, including exports/backups. Responses may be reconstructed from immutable references; do not prune deduplication identity and permit duplicate evidence. `If-Match` is the resource revision; `X-Profile-Epoch` prevents a pre-restore client modifying replacement data. Multiple tab edits use separate context/draft identities and optimistic concurrency, never last-writer-wins.

## Draft, attempt and support lifecycle

`editing → submitted → checked | unresolved` is an attempt's original lifecycle. The learner can create a new attempt or an explicit revision attempt linked to a previous one; they cannot mutate a checked original answer. Draft autosave debounce is 500 ms, plus blur/navigation/check flush. Show `saving`, `saved` only after revision ACK, or `not saved` with retry. Keep input and a recovery outbox in IndexedDB on failure. Outbox entries contain operationId, epoch, context/draft IDs, base revision and text; encrypting browser storage is not claimed. Server state is authoritative. Reconciliation checks all preconditions; a conflict creates a separately displayed recovered draft rather than overwriting newer data. Clear acknowledged outbox entries. No answer is graded while its durable submission failed.

Submit pins normalized and original answer, task/key/audio revisions, target IDs, support snapshot, activity context and clock. The original answer remains private. Evaluate once per submission; a duplicate returns its receipt. Browser navigation or a failed request does not fabricate an attempt. After a result the learner explicitly presses Next. Returning to another route keeps the saved draft and exercise location. A port change may make an unacknowledged browser outbox inaccessible at the new origin; prior-port reuse and a visible copy/export recovery action are required, and such a draft must never have been labeled Saved.

Support events record actual delivery, target(s), kind, source (`ui`, `agent`, `learner-report`), context, active draft/attempt and timestamp. Kinds: `interface-help` (neutral), `replay`/`speed-change` (neutral), `rule`, `targeted-clue`, `translation`, `transcript`, `reveal`, `external-help`, `delivery-unknown`. Rule help affects only explicitly mapped current targets it actually explains. If relevance is unclear, mark evidence uncertain, not all skills wrong. A vocabulary clue does not become a conjugation failure. Help outside an active assessed task records exposure; it does not invent a failed attempt. Independent review eligibility for that target is postponed until a later calendar day after targeted exposure.

External help is prepare → deliver → confirm, see API.md. Preparation alone is not evidence of language difficulty. Pending delivery at submit or lost delivery confirmation makes only the potentially affected target's independence `unknown`; it may not receive independent credit. Confirmed undelivered cancellation leaves no support penalty. After the learner has checked an attempt, ordinary explanatory review is a separate event and does not rewrite the original assistance snapshot. A late confirmed-undelivered external reservation may clarify history but does not automatically turn a submitted unknown result into independent success; an evidence-backed adjudication is needed. UI-mediated never-rendered help is known undelivered before submit and is neutral. A later explicit disclosure that help preceded submission appends a provenance-bearing correction and rebuilds the affected projection; preserve the original record.

## Checking and adjudication

Correctness (`correct`, `incorrect`, `unresolved`, `invalid-item`) and independence (`independent`, `supported`, `unknown`, `not-assessed`) are separate. Target results include an explanation key, matched accepted-variant ID or deterministic rule ID, and attributable evidence. Confidence is not an unexplained model percentage. An answer can be correct with support; an unresolved target is neither a pass nor a failure. A clearly established error in one target can be recorded while a different target remains unresolved. Unattributable overall mismatch stays unresolved for all affected targets.

Deterministic pipeline: Unicode NFC; trim edges/collapse ordinary whitespace; apply only the task's explicitly reviewed case/punctuation policy; compare reviewed variants or a typed finite transformation rule. Never globally remove accents/ñ, reorder words, fuzzy-match meanings, infer grammar from edit distance, or accept substring matches. Case/punctuation tolerance is allowed only where it does not assess that feature or alter meaning. Exact-writing targets preserve relevant marks; meaningful tú/tu and él/el distinctions remain meaningful. Distractor sets and text/rules are versioned and cross-reviewed. Arbitrary grammar code/regular expressions provided by agents are forbidden. Finite answer templates must enumerate validated slots, agreement and accepted outputs.

Task checking modes: `choice` (stable option ID), `exact-variants`, `finite-slots`, `rubric-review` (free text starts unresolved). Content also contains concise Ukrainian feedback, targeted hints and reviewed reference answers. A reference is an example where alternatives are possible. Free writing must never receive an automatic blanket failure simply because it differs from that example. Learner self-reports can request more review or flag an item; they do not certify correctness or create independent success.

External review exports a **selected, explicit** task/answer packet only after learner action, with the private-data notice and exact fields shown. A submitted review becomes a draft adjudication: provider/model/effort, exact answer/task/rubric revisions, per-target verdicts, evidence citations, uncertainty and actual support declaration. To change a linguistic verdict automatically, require a fresh opposite-provider corroboration or a directly verified authoritative reference supporting that exact distinction, plus the local review tool's signed validation receipt; contradictory/unsupported cases remain unresolved. Ordinary agent tokens cannot sign/promote their own packet. The CLI review-import command validates provenance/schema/revision and permits only adjudication/content status, never fabricated attempts. It asks for no routine owner linguistic decision.

Adjudications are append-only, linked to the original attempt and review records, with supersession links. Recompute that target's schedule chronologically from valid evidence and corrections; preserve unrelated state. Do not add multiple stage advances for one attempt or reward the later review date as a new recall event. An invalid item is quarantined, its evidence excluded from affected projections, and a repair task queued; known variants/lessons stay available. When evidence is invalidated or newly resolved long after submission, overdue checks become eligible now, with no absence failure. History shows the correction and why.

## Scheduler — exact initial algorithm

Use an injected UTC clock and persisted IANA timezone, initial `Europe/Madrid`. `today` is its calendar date; add calendar days, not 86,400-second multiples. Each target keeps `stage` 0–4 for intervals `[1,3,7,14,30]`, dueDate, lastExposureDate, lastEligibleDate, pendingNeed, latest relevant support/error, pause flag, frequency preference and knownStep. Introduction sets stage=0 and dueDate=tomorrow without any pass. Unintroduced/unchecked-draft targets never enter automatic review.

Eligible delayed success requires: correct + independent on that target; ready valid item; no targeted exposure on the same calendar day; at least one calendar day after previous assessed exposure; dueDate reached; and no prior eligible advancement for the same target/date. A manual attempt can qualify under the same conditions, including while paused, without removing pause. Distinct held-out prompt/context or listening asset is required for an advance if the immediately preceding eligible check used the same one. Reordered choices or the same memorized recording alone are not a new context. If no eligible varied item exists, offer labeled extra practice without advancing and surface the content shortage to the maintainer.

Process events in eventSeq order:

1. Relevant clear error, delivered targeted help/reveal, or supported correct result sets stage=0, pendingNeed=true, knownStep=disabled, and dueDate=tomorrow; preserve all historical successes. Neutral help/replay and unresolved results do not change dueDate/stage. Unknown support blocks independence credit without manufacturing an error. A correct immediate repetition does not clear pendingNeed.
2. Eligible delayed independent success clears pendingNeed, increments stage by one up to4, and schedules from the **actual check date** by that stage's interval. Only one advance per target/date/attempt. At stage4 the next interval remains30.
3. Ordinary independent extra practice before dueDate is exposure and history, not delayed-stage advancement. It may postpone same-day eligibility, but must not silently postpone the already scheduled dueDate. Missed dates create no events/failures and no multiplied quota.
4. Apply active frequency controls below to new due dates; pause filters the automatic queue rather than erasing dates.

Frequency and pause are orthogonal. `usual`, `repeat-more`, `known` are mutually exclusive frequency choices; pause is a separate boolean. Repeat-more sets dueDate=min(existing,tomorrow) and caps new successful intervals at7, preserving the underlying evidence stage. Switching to usual retains the current dueDate; subsequent success uses the preserved stage. Known without pendingNeed sets dueDate=max(existing,today+7) and knownStep=0; it records no pass. Its qualifying check schedules14 days (knownStep1), next30 (knownStep2), then30. The ordinary evidence stage still advances by only one per actual eligible success. Stable evidence retains any already appropriate longer dueDate. Relevant error/help disables Known acceleration and gives next-day review; the Known label remains a preference with a visible “recent support takes priority” explanation. Normal ladder applies until the learner deliberately selects Known again without pendingNeed. Regaining the stable label alone does not reactivate Known acceleration; only an explicit Known reselect without pendingNeed does. Pause overrides every automatic lane, including Known/Repeat-more. Resume retains future dueDate; if overdue it is eligible today. Manual practice never resumes it implicitly.

Stable in later checks means the latest three eligible outcomes are independent successes on distinct dates spanning ≥7 calendar days, at least two prompt/context families (and two audio hashes for listening), with no later relevant support/error/invalidating correction. Supported/uncertain/introduced states remain visible separately. A later error changes the current label but does not delete those past successes. This is a UI evidence label, not CEFR certification or proof of permanent retention.

Queue input: selected scope (default all introduced ready targets), chosen modality, time preference5/10/20 min (default10) or manual item count (default10,max30). Estimate60sec/item until at least10 real attempts in that mode, then use median of bounded5–180sec active times; no timing-based grading. Count cap=min(30,ceil(minutes×60/estimate)); at least1. No new lesson is inserted into review without explicit choice.

Build due lanes: R=repeat-more; S=pendingNeed excluding R; O=all other due. Paused/unready/out-of-scope excluded. Weighted persistent round-robin pattern `[R,S,O,R,O]`; skip empty lanes. Within each lane sort `lastOfferedSequence` ascending (never offered first), then dueDate ascending, then stable target ID. Persist cursor and offer sequence only when the learner starts the proposed session; viewing home does not consume priority. This gives older/less-offered targets turns across short sessions without starving support. At most one scored item per target in the initial set; a learner may explicitly request extra practice. Store a session queue snapshot; content quarantine removes an invalid item with a visible reason, never substitutes outside scope. Select the least-recently used eligible held-out task, tie by taskID/revision. No randomness in grading or queue priority; optional prompt shuffle uses stored session seed only.

Timezone changes are an explicit profile setting with preview: keep historical UTC and local dates, stage and existing dueDate labels; use the new zone for future event dates and new intervals. Clock moving backward preserves eventSeq ordering, caps advancement to one per target/local date and shows a diagnostic; no negative elapsed-time inference. DST/travel tests are required. Do not auto-change timezone from the OS.

## Versioned offline installation

A pack manifest lists schemaVersion, packID/version, minimum app/schema, every immutable text/task/media revision, byte size/hash, language/variety, review/rights evidence and coverage digest. All A1–A2 required assets are installed before activation. Verify hashes/references/Ready gates in a staging directory, take a pre-change snapshot, then transactionally switch the active manifest pointer. Crash before switch leaves old pack; crash after switch must find the full verified new pack. Keep prior revisions while referenced by attempts, drafts, active rollback packs or retained backups; do not garbage-collect by age alone. No remote URL is a required practice asset. Audio uses local MIME-checked assets/range requests. Missing/corrupt media is an error, never listening success.

Without external internet, fresh unseen lessons, audio, grading, drafts, summaries and review work while the local service is running. Closing/restarting the browser and server must preserve them. If the local service is stopped, show connection/recovery guidance; no promise of a standalone offline phone/PWA. No service worker cache is the authoritative database.

## Backups, export and replacement restore

On startup and after a committed learning/content/draft/preference change (not backup registration, health/auth reads or runtime housekeeping), schedule a backup when the current local day lacks one or its snapshot is older than the latest eventSeq; debounce changes for60sec, at most one refresh/15min. A clean stop flushes a changed day's snapshot. No wakeup when the service is off. Retain seven latest changed-day snapshots and four ISO-week snapshots, reusing verified files by references, not duplicate bytes. Keep five newest successful pre-change snapshots (migration/content activation/restore) plus the latest verified rollback for the active transition. A current failed change does not prune its required rollback. Backups on the same disk do not cover disk loss; explain optional manual export elsewhere.

Pause writer queue during online `db.backup()` to pin eventSeq, timeout30sec and retry later without discarding data; then reopen temporary backup read-only and check `quick_check`, foreign keys, schema/profile/eventSeq and SHA-256. Flush file/directory, atomic rename, then register/prune only verified superseded snapshots. Never copy a live main SQLite file without WAL consistency. Verification failure retains the previous valid snapshots and reports neutral recovery status. Disk pressure offers export/cleanup preview; never deletes the only valid backup automatically.

Portable export is a ZIP with manifest and logical versioned JSON/NDJSON records plus private assets when relevant; include immutable attempts/support/adjudications/preferences/receipts/content references, omit active credentials/session cookies/runtime PID/URL/logs. Ready core content may be referenced by pack hash; include any private revisions needed to interpret history. Show whether external core pack files are required and include an option for a self-contained portable bundle. Logical import never executes SQL, triggers, scripts or supplied schema.

Limits:512MiB compressed,2GiB expanded,10,000 entries,240 UTF-8 bytes per path; reject absolute/traversal paths, symlinks, duplicate/case-colliding paths, unknown executable entries, size/hash mismatches, unsupported future schema and missing required packs/references. Stream with bounded decompression; reject once a bound is exceeded. Import into an isolated new DB through prepared inserts and application migrations, check every FK/digest and dry rebuild projections. Never alter the live profile during validation.

Restore preview returns profile ID, counts/date/schema, replacement warning, missing assets and a single-use expiring confirmation bound to the exact validated archive hash/current eventSeq/epoch. Only owner UI/CLI can confirm; no agent capability. On confirm: reject changed source/live state; stop new mutations/drain saves; verified pre-restore backup; close/checkpoint; build and fsync shadow profile on the same volume; rename/switch with a crash-recoverable journal; reopen and verify. A failed step restores the old DB/assets and confirms health before leaving maintenance mode. A successful switch sets profileEpoch=max(previous live epoch, imported epoch)+1 (abort safely on integer overflow), writes the restore operation/hash/outcome marker into the shadow profile/journal before activation, invalidates contexts/sessions/all tokens/cookies/nonce, and asks launcher to reopen/re-authenticate. Exported receipt identities remain for deduplication, but old-epoch requests fail. Historical review HMAC keys are not portable; API.md defines keyId, unknown-key source-trust preview and local import attestation. Preserve imported ready records/history with their original provenance, never claim a new model review or allow an imported receipt to certify an edited revision. Never merge two devices' profiles in this release. A recovery drill must demonstrate both successful replacement and injected post-switch rollback.
