# Complete A1–A2 content production and review

This specifies future authoring. No task bank, recording, model calibration or linguistic certification is delivered by this planning PR. [Curriculum](CURRICULUM-A1-A2.md) supplies accepted IDs/groupings and source anchors; [ledger](contracts/curriculum-ledger.json) reproduces the actual definition rows. The original objective/lesson counts do not prove atomic inventory coverage. [Domain](DOMAIN-SPEC.md) defines evidence and checker constraints.

## Inventory before bulk generation

WP-04 expands each of the107 broad objectives into atomic target rows without renumbering it. Required fields: skillId, parent objective(s), skill kind/modality, exact forms/meanings/exception scope, first-teaching lesson, prerequisite skill/word IDs, short Ukrainian rule and staged support, assessed vs incidental material, practice/check/later-return assignments, authoritative source passage, adequate-context/valid-variant policy, task-family/held-out allocation, clip/collection links, and review status/evidence. CV-01–CV-06 must appear as explicit first-teaching/return rows, not only a note. Every89 lesson and14 optional check gets a runnable ordered content manifest. A1 foundations may be skipped voluntarily; no skipped target receives tested success.

Produce `content/source/coverage.json` plus source/lexicon/skills/tasks/audio/lessons/collections manifests validated against application schemas. Record inventory counts per block/modality and a digest in the pack. No `TBD`, missing source, unchecked draft or unknown key may be marked Ready. Gaps stay `needs-review`; a developer repairs them without reducing scope. Lesson IDs/counts stay stable; add short internal steps for CV allocations. If a lesson exceeds20min independent of optional practice, split presentation into labeled resumable steps under the same lesson ID and document it; changing accepted lesson/objective counts requires a separate visible plan revision, not silent renumbering or a new owner questionnaire.

Authoring scope rules (these are production constraints, not validated Spanish keys):

| Family | Required inventory granularity |
|---|---|
| Foundations/agreement | Relevant letters/accents/punctuation, noun+article identity, common gender exceptions, singular/plural and adjective/possessive agreement. Meaningful accent pairs have independent targets where actually assessed. |
| Person/form paradigms | Introduce all six grammatical person-number slots progressively, with Spain-relevant vosotros and usted/ustedes reference. Every taught tense/pattern has a reviewed paradigm; target per contrast/irregular/person group, not one “tense learned” boolean. Person membership and syncretic ambiguities explicit. |
| Present | Regular -ar/-er/-ir; ser/estar/hay/tener; A2 pattern/individual exceptions, reflexive routines/placement where allocated. Candidate high-frequency inventory includes ir, hacer, querer, poder, venir, decir, poner, salir, saber, conocer, dar and ver, plus representative e→ie/o→ue/e→i groups. Cross-check exact level/source allocation rather than asserting all candidate uses belong in A1. |
| Perfecto | Haber form vs participle vs word order vs invariance vs contextual choice. Mandatory individual targets include hecho/dicho/escrito/visto; review and allocate other frequent irregular participles (e.g. puesto/vuelto/abierto/roto/muerto) and -ído spelling separately. “All -ir end -ido” must never become an unrestricted rule. |
| Indefinido | Regular paradigms, orthographic/accent changes, vowel/y changes, frequent irregular stems/endings and contextual ser/ir interpretation. Explicit verb/person inventory; do not grade an untaught irregular by analogy. |
| Imperfecto/contrast | -aba/-ía, ser/ir/ver exceptions, habitual/background/description contexts; contrasts with bounded events/perfecto have sufficient context and allow reviewed regional/context alternatives. No universal mechanical hoy/ayer-only key. |
| Reference/instructions | Direct/indirect reference, placement, combined pronouns, agreement, comparison, relative que; affirmative commands tú/vosotros and usted/ustedes, frequent irregulars and clitic stress. No silent productive negative-imperative/subjunctive module. |
| CV/support | Early fixed formulas/listening; muy/mucho, también/tampoco, nada/nadie; taught preposition/diacritic frames; age/weather/time links before past use; bounded hay que/acabar de/empezar a/volver a; situation/genre map. First-use teaching precedes assessment. |
| Texts | Reading/writing begin early: labels/forms, menus/prices/schedules/notices, messages/replies, descriptions and past accounts. Comprehension, spelling and communicative appropriateness are separate. Free text uses an explicit rubric and unresolved pathway. |

Exact candidate lexical/form lists are frozen and reviewed in WP-04 before task generation; the table supplies minimum families, not verified conjugation tables. Source reconciliation may discover a missing foundation. Add a taught microstep and ledger link, not an unexplained prerequisite. No claim of official CEFR certification, speaking competence or a complete Cervantes inventory from these source anchors alone.

## Bank sizing, variety and authoring units

Baseline per small productive grammar target:10 reviewed task instances, within accepted8–12 calibration target. Allocate2 supported learning,4 independent practice,4 reserved delayed/transfer prompts, with≥2 context families and≥2 task types where meaningful. A task may cover multiple targets only with explicit independently checkable mappings; the ledger deduplicates instances and proves per-target coverage. Irregular exceptions each get distinct recall support/checks, not ten tasks for a whole tense. Word/character targets may share tasks; any smaller/larger allocation needs a written coverage justification and cross-review. No overall “107×10” shortcut.

Listening target: at least2 separately generated/reviewed recordings with distinct utterance/context, not speed-transformed copies;≥1 meaning task per clip, optional separately graded dictation. Introduce a greeting/formula as a whole when its internal grammar is untaught. Include everyday Spain use such as the owner's shop/greeting examples after review, then short sentences and brief connected texts. A1 short clips2–15sec, A2 utterance/text clips10–60sec; split longer recordings into resumable tasks. These are production bounds, not mandated learner listening speed. A2-08 contains a connected short recording and distinct written response.

Practice selection uses reviewed concrete instances first. A finite template may vary only typed, taught slots with verified agreement/meaning and explicit accepted outputs; it must not create an unseen key or ambiguous context at runtime. Maintain held-out prompt/context IDs to avoid immediate copying masquerading as delayed recall. When variety runs out, label familiar extra practice and preserve the shortage in the coverage report; no advance from exact repeated material alone.

Eight original prepared collections of12 ready shared phrase references each: greetings/social formulas; shop/food; transport/time; appointments; home/accommodation; routine/study/work; requests/simple problems; experiences/past messages. A phrase can belong to several packs with one history; all96 memberships must be covered, not necessarily96 unique phrases. Course packs are immutable versions; “make my copy” creates a personal collection referencing the same phrase identities. Personal free capture has no minimum volume and starts as a draft. Provide exact-phrase recall plus separately reviewed construction variations. No personal records in public fixtures.

## Text review matrix and workflow

The owner has no human language reviewer. Use references plus fresh-context cross-provider review; neither a second model's confidence nor Google Translate is ground truth. Current model settings are a recommended starting point, to be calibrated on the actual tasks:

| Job | Author | Independent reviewer | Disagreement route |
|---|---|---|---|
| Ordinary rule/examples/tasks/variants | GPT-6.1 Sol `high` | Claude Opus5.5 `medium` | Sol `xhigh` and fresh Opus `xhigh`, exact source passages |
| Claude-authored alternative batch | Claude Opus5.5 `medium` | GPT-6.1 Sol `xhigh` | fresh source-first review; no majority vote |
| Hard tense/reference/valid-alternative dispute | Assigned above, narrowed packet | Opposite provider at `xhigh` | unresolved/quarantine if evidence remains insufficient |

Record actual provider/model ID/version/effort/date/tool, complete content revision hashes, author vs reviewer separation and review findings. Never claim that Codex/Claude product names alone identify an underlying model or provide audio input. No same-provider fallback counts as the opposite-provider Ready gate. If a tool lacks the selected model/effort, probe its actual capabilities, choose the nearest available opposite-provider setting with a documented calibration rerun; otherwise leave needs-review. No Fable/max-effort default or recurring cost is required.

Review packet contains exact proposed content, source passages/links and mapped targets/prerequisites, keys/alternatives/distractors, Ukrainian explanation, hints/rubric and context restrictions. Reviewer must search for false rules, valid rejected alternatives, answer leakage, unknown prerequisites, regional overclaims, poor Ukrainian, wrong level/meaning, and conflicting feedback/support attribution. Independent reviewer gets the source packet and task, not an author's “already correct” assertion. Record verified citations and unresolved claims separately. Reading a URL title/indexed extract is not verification of its full contents; retrieve exact passages during production and respect source copyright.

Readiness progression: draft → source-mapped → reviewed findings → author repair/new revision → fresh opposite-provider verification of changed material → local validation receipt → ready. A revision change invalidates the prior hash-bound review/media receipt. Preserve previous ready revision until replacement passes. No ordinary agent can set ready directly. Text generator output is never automatically a practice answer model.

## Calibration before mass production

Create40 reference-backed cases with hidden labels:16 flawed (wrong form/rule/stress/meaning/prerequisite/key/feedback),16 valid controls (including genuine acceptable alternatives),8 intentionally ambiguous/context-insufficient cases. At least12 cover tenses/participles,8 reference/agreement,8 orthography/prerequisites/Ukrainian feedback,12 listening transcript/meaning or mixed applications; category tags may overlap but each case has a primary category totaling40. Keep labels out of reviewer context and separate authoring/calibration material from release tasks.

A separate source-verification pass checks each label/passage before benchmarking. Require zero missed release-blocking errors, zero valid controls rejected without source support, ≥95% seeded substantive defect detection (round up), and ≥90% ambiguous cases recognized as uncertain (round up). False positives must have sources and be adjudicated; passing numerical thresholds does not waive a wrong answer key. Run both author→reviewer directions on the packet. Repair prompts/effort/context/schema and rerun fresh held-out cases, maximum2 repair cycles before changing the workflow/provider and recording the blocker. Do not shrink the truth set to make scores pass. Report precision/recall/error table and all uncertainty; this calibrates a workflow, not the full corpus or language-learning effectiveness.

## Audio production, budget and actual-file QA

Candidate default is ElevenLabs `eleven_multilingual_v2`, a Spain-Spanish voice selected by a measured sweep. Do not select a voice ID from memory or assume a provider's Spanish label guarantees a Spain accent. Sweep3 candidate voices ×6 reviewed scripts: greeting/shop formula, amounts/time, question/negation, pronoun/command stress, participle/past contrast and short connected message. Store actual voice IDs/settings/model/revision/date/transcript/seed if available/raw and normalized asset hashes, sample rate/codec/duration and generation/rights evidence. No voice cloning or commissioned speaker work.

Use MP3 for browser playback, target44.1kHz/128kbps mono, loudness approximately−19 LUFS mono/peak≤−1dBTP where normalizing is available; keep originals and document actual conversion tool/version. Do not treat format/loudness checks as language QA. No music/noise/effects. Default speed1; optional0.85 using browser playbackRate, no fake evidence penalty. In-browser replay button/user gesture and iOS audio behavior need actual tests.

Budget planning: approximately$5–10 for the **initial batch**, not a guarantee for all A1–B2. At the research snapshot ElevenLabs standard Starter is$6/30,000credits before tax and multilingualv2 uses one credit/character; ignore temporary promotion prices. Count scripts + variants + candidate sweep + failed takes before any spend. Reserve≤24,000 useful-script characters and≤6,000 sweep/retake credits inside a30,000-credit candidate batch; actual checkout tax/conversion and any audio-review fee must stay inside the explicitly authorized cap. This plan authorizes no purchase. Never auto-renew, add overage or assume a saved billing account. If a paid subscription is the only checkout route, prepare the exact one-cycle purchase/cancellation controls for owner authorization; no recurring billing by inference. Additional batches require a concrete new approval or a valid free/local route.

Fallback tree: (1) use authorized existing quota/one-off credits if measured voice/rights/cost gates pass; (2) benchmark local Piper `es_ES-davefx-medium` with a pinned model revision/hash and tool/model/output license review; (3) another verifiable Spain TTS or existing suitable licensed recording, same gates; (4) report blocked required audio rather than ship text-only as complete. The Piper model card's dataset CC0 notice is evidence about that dataset, not blanket proof of model/output redistribution rights. Do not hide budget overflow by removing required listening coverage. Bank count/clip deduplication can reduce cost only while coverage/variety remains satisfied.

Actual-file reviewer candidate: stable Gemini `gemini-3.8-flash` through an authorized audio-capable API/tool, plus an independent blind transcription job for mismatch detection. First-release ASR detector uses a separate fresh Gemini3.8Flash audio transcription call without the reference script, followed by deterministic word/amount/negation comparison against the reviewed transcript. “Independent” here means a separate blind job, not a second provider; it detects mismatches and does not prove pronunciation/naturalness. The file-with-reference quality review is a separate job. Probe actual file ingestion first using a synthetic calibration file; a text transcript pasted into a text-only model is not an audio review. No runtime Gemini dependency is added to the learning app. No new paid account/billing is silently created. If this route is unavailable, substitute a measured actual-audio-capable reviewer or leave the gate blocked. Do not use the deprecated GPT-Audio snapshot as a default.

Audio calibration is a distinct20-file set:8 correct controls,8 seeded defects (wrong/missing word, wrong stress, wrong amount, transcript mismatch, corruption/clipping, unsuitable accent claim),4 uncertain pronunciation/meaning cases. Verify labels by references and actual audio analysis; record any phonetic judgment still unconfirmed. Require zero missed blocking defects, zero unsupported control rejection and all uncertain cases flagged. Text cross-provider review remains mandatory for transcripts/keys; audio QA adds, rather than replaces, it.

Per release clip require: hash/format/playability; actual transcript alignment with no substantive omission/addition; correct amounts/negation/stress; natural intelligibility and defensible Spain-variety judgment; exact task/transcript/help alignment; actual file review receipt and explicit uncertainty; rights/provenance record and allowed local/distribution uses. Synthetic audio must be labeled as synthetic. An automated accent/naturalness judgment is a model assessment, not human-native certification. Any doubtful required clip is regenerated/replaced/reviewed. Store ready clips locally, reuse without online subscription. No future paywall/license expiry may silently make installed required practice inaccessible; verify terms for generated assets before committing a provider.
